Forms: a light field layer, pure validation and a renderer registry. All additive: with no new props, no registry and no provider every existing form renders and behaves as before (characterisation snapshots of FormElement, FieldInput, ColourField and ColourPickerPopover are unchanged).

**@bcl32/forms**

- `@bcl32/forms/validate` (new subpath, pure, Node-safe; imports only `@bcl32/data-utils/numbers`): `validate(attrs, values, opts)`, `validateField`, `textLength` (code points after NFC; plain Pydantic counts code points without normalising, so a server that must agree normalises first, e.g. a `BeforeValidator`), `isEmptyValue`, `issueText`. Rules: required (`attr.required`, a non-nullable null number, `""` with `min_length >= 1`), `min_length` / `max_length`, named `charset` policies that report the offending characters, `pattern` as an unanchored search like Pydantic (an uncompilable pattern is skipped, never thrown), number bounds / integer / decimals on the value, a select's options, the registry's per-type rule, cross-field rules and `x-` custom codes. `trim` (default off) strips a string before the required, length, charset and pattern checks, as Pydantic's `str_strip_whitespace` does (Unicode White_Space, not JS `trim()`); `resolve` picks a registry entry per attribute, as FieldSet's does. Works on a structural `FieldBase` / `RuleSource`: a generated `ModelAttribute` fits with no cast, and so does a hand-written descriptor. Opt-in: nothing calls it yet, and `fieldErrors` output is unchanged; `fieldErrorText` now delegates to `issueText` with identical words.
- `@bcl32/forms/fields` (new subpath, renders on a server with no providers, never imports hooks, react-query, sonner, dayjs, Combobox, DateTimePicker, Tooltip, RelationCollectionField or ColourField): `FieldInput` (now public; props unchanged, plus optional `size`, `classNames` and `inputProps`; a descriptor's `min_length` / `max_length` become native `minLength` / `maxLength`; `boolean` is a native checkbox here, while FormElement, EditableDetailItem and RelationCollectionField keep the Radix one), `FieldShell` (plain label, inline hint, error), `FieldSet` (controlled, returns a new object) and `useFieldSetState`, `FieldRegistryProvider` (`registry`, `resolve`) / `useFieldRegistry` / `useFieldResolver` / `mergeRegistries` and the `FieldRegistry` / `FieldRenderer` / `FieldRenderProps` / `FieldResolver` / `FieldInputHTMLProps` types, `lightRenderers`, `FieldStyleProvider`. About 13 KB gzip (no Radix checkbox).
- Choosing a renderer per attribute: `resolve(attr)` on `FieldRegistryProvider`, `FieldSet` and `FormElement` returns a registry key. That key is looked up first, through every registry in order (props, provider, then `lightRenderers` on a FieldSet), then `attr.type` as before; undefined, null or a key no registry holds falls back to the type. A prop's `resolve` is asked before the provider's, nested providers inner first. So a page can draw some selects as radio cards without registering `select` and replacing them all. `canRenderFormElement(attr, renderers?, resolve?)` and the Edit / Bulk-edit forms honour it.
- `FieldRenderProps.label`: the label the shell shows (`fieldLabel(attr)`, no suffix or mark), for controls that draw their own legend.
- The optional mark shows only on a field that may really be left empty: not `required`, and `nullable`, or with no non-empty `default` and nothing `validate` refuses empty (a non-nullable number, `min_length >= 1`). A choice with a default no longer reads "(optional)".
- `inputProps` on `FieldInput`: extra attributes (`autoComplete`, `spellCheck`, `enterKeyHint`…) for the element it draws. The keys FieldInput owns (`id`, `name`, `value`, `onChange`, `onBlur`, `type`, the class, `aria-*`, a number's `step` / `min` / `max`, the descriptor's limits) are left out of the type and dropped at run time. The browser's `maxLength` counts UTF-16 units without NFC, so it is never looser than the server's code-point limit (save the few characters NFC expands, such as U+FB2C); `validate` stays the check that agrees with the server.
- `FormElement` gains a `renderers` prop and reads `FieldRegistryProvider`: a registered type is drawn before the built-in switch, which is untouched. `canRenderFormElement(attr, renderers?)` knows registered types (a non-object second argument is ignored, so `.filter(canRenderFormElement)` still works). `EditModelForm` and `BulkEditModelForm` read the context, so forms hosted by `@bcl32/datatable` see a provider without a datatable release.
- `FieldInput` forwards `invalid` / `describedBy` as `aria-invalid` / `aria-describedby` on every type; nothing is written when neither is passed.
- Styling: `size` (`sm` = today's compact, `md` = today's default, `lg` = 48 px, text-base) and `classNames` slots (root, label, legend, optional, hint, control, input, error) on `FieldShell`, `FieldInput` and `FieldSet`, merged with tailwind-merge. Unset, the markup is byte-identical.
- `@bcl32/forms/ColourFieldView` (new subpath): the colour field with swatches as a prop and no fetch. `ColourField` is now its fetch plus this view, with the same props and markup, and also accepts `allowCustom` and `renderSwatchIcon`. Its popover now closes on Escape and returns focus to the trigger, instead of Escape reaching (and closing) a dialog behind it.
- SSR: `RelationCollectionField` reads its folded sections only when there is a window (still synchronously on the client, so nothing flashes open); `AutoGrowTextarea` and the folded-note measure use an isomorphic layout effect; the dayjs utc/timezone setup moved from four module-scope copies into one `datetimeSetup` module used by the datetime renderer.
- `@tanstack/react-query`, `dayjs` and `sonner` are now optional peers (`peerDependenciesMeta`); the CRUD forms still need them, as before.

**@bcl32/utils**

- `ColourPickerPopover`: `allowCustom` (default `true`) hides the Custom colour input when false; optional `onClose`, called on Escape, which then stops at the popover (a dialog behind stays open) and returns focus to the element that had it when the popover opened. Without `onClose`, Escape is untouched. Default markup is unchanged.

**@bcl32/data-utils**

- `ModelAttribute` and `MODEL_ATTRIBUTE_KEYS` declare the keys schema_utils 0.24.0 writes, all `generated`: `required` (written only when true: the field is in the Create schema's `required` list), `min_length` / `max_length` (code points), `pattern` (an unanchored search, like Pydantic), and the layout and charset extras `group`, `order`, `charset`. Types only; nothing reads them in data-utils. Forms' `RuleSource` accepts a `ModelAttribute` with no cast.
